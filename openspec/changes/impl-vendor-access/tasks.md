# Tasks

Кожна група — окремий PR «Реалізація» (`task/<коротко>`); галочки групи ставимо в її PR. Перед кодом сторінок читаємо гайд у `node_modules/next/dist/docs/`. Міграції — лише новими файлами через `npx supabase migration new`, мітка новіша за `origin/main` (`node scripts/check-migration-order.mjs`). Перед комітом і PR: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run ac:coverage`, `npm run spec:check`, `npm run spec:validate`, `npm run check:design`, `npm run check:boundary`. Кожна Server Action починається з `requireRole(...)` (або `getClaims()`), роль — з `profiles.role`, ніколи з `user_metadata`. У кожній групі: тест на кожен відмовний AC (відмова **і** «дані не змінились»), назва тесту починається з AC ID, очікування в `expect` — значення з «Тоді»; тест пише нова сесія агента до коду або окремо від нього (maker ≠ checker, промпт F02 домашки WS9); мутаційна перевірка (таблиця «AC → що прибрали → який тест упав»; SQL-мутант `npm run mutation:sql` → `KILLED` або видимий червоний прогін CI, revert лише після нього). Рядки AC групи в `docs/conformance.md` — у тому самому PR («реалізовано» лише з непропущеним тестом). Вендорів у базі (`npm run users:demo`) до групи 5 не створюємо.
