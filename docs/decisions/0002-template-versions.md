# 0002. Версії шаблонів: знімок на кожне збереження, робоча копія лише для адміністратора, запис функціями

- Статус: прийнято
- Дата: 2026-10-27
- AC: AC-EDITOR-01, AC-EDITOR-02, AC-EDITOR-03, AC-EDITOR-04, AC-EDITOR-05, AC-EDITOR-06, AC-EDITOR-07, AC-EDITOR-08, AC-RUN-02, AC-RUN-12

## Контекст

Вимога PM (solomchaak/property-workflows-spec#20) — адміністратор редагує шаблон, зміни зберігаються автоматично, а збереження створює пронумеровану версію; менеджер бачить лише поточну збережену версію й ніколи — непублікованих змін чи списку версій; запуск зберігає версію, з якої створений. Правила мають діяти й тоді, коли запит іде напряму в Data API (AC-EDITOR-08), бо публічний ключ лежить у бандлі. supabase-js не має транзакцій. До цього зрізу шаблони читали всі автентифіковані користувачі, а писав лише `service_role` (ADR 0001). План — `openspec/changes/impl-templates-editor/design.md`.

## Рішення

- **Робоча копія + знімок.** Непубліковані зміни живуть у наявних `template_sections` і `template_tasks` і читає їх лише admin. Збереження версії копіює робочу копію в `template_versions` → `template_version_sections` → `template_version_tasks`, і знімок після цього не змінюється. `templates.current_version` вказує на поточну версію (складений зовнішній ключ `(id, current_version)` → `template_versions (template_id, version)`), `runs.template_version` — на версію запуску (складений ключ на `template_versions`). `section_id` задач знімка — нові id секцій версії (мапінг за позицією), складений ключ `(section_id, version_id)` не дає задачі посилатися на секцію іншої версії.
- **Запис лише функціями.** `authenticated` має тільки `select`. `public.create_template`, `public.save_template_draft`, `public.publish_template` (`security invoker`) викликають `private.*` (`security definer`, `set search_path = ''`), і **першим рядком** кожна перевіряє роль `admin` (інакше `FORBIDDEN`, `42501`). Автозбереження (`save_template_draft`) лише замінює робочу копію й версію не створює; знімок створює тільки `publish_template` (відмова `A template needs at least one required task`, якщо немає обов'язкової задачі; без змін версія не створюється).
- **Видимість (RLS).** Менеджер бачить шаблони лише з `current_version is not null`; знімок читає admin або будь-хто, якщо версія — поточна для свого шаблону (хелпер `private.can_read_template_version`, `security definer`); `template_versions`, `template_drafts` і робоча копія — лише admin. У секціях знімка продубльовано `template_id` і `version`, щоб менеджер знаходив поточну версію за шаблоном, не читаючи `template_versions`.
- **Запуск зі знімка.** `launch_run` (та сама сигнатура) копіює секції й задачі знімка поточної версії, записує `runs.template_version`; шаблон без збереженої версії не запускається ніким. `template_task_id` у `p_assignments` — id задачі знімка.
- **Відхилення від плану.** Прапорець «є непубліковані зміни» живе в `template_drafts` (лише admin), а не колонкою в `templates`, бо `templates` читає менеджер, і факт наявності чернетки йому бачити не можна. У плані (`design.md`) прапорець описано як колонку `templates`.
- **Бекфіл.** Для наявного «Tenant move-in» і його запусків створено версію 1 (рішення до solomchaak/property-workflows-spec#33).

## Розглянуті варіанти

- Версія як рядок із `published = false` для чернетки — політики видимості менеджеру ускладнюються, знімок простіше тестувати.
- Версії в JSON-колонці — ламає копіювання в `run_sections`/`run_tasks` і запити за прапорцем `required`.
- Прапорець чернетки колонкою `templates` — менеджер міг би прочитати його через Data API.
- Server Action з admin-клієнтом (секретний ключ) замість функцій бази — правило ролі жило б лише в коді, а секретний ключ потрапив би у Vercel без потреби.
- Роль у JWT (Custom Access Token Hook) — роль у токені застаріває до оновлення, потребує налаштування хука й емуляції в тестах.

## Наслідки

- Простіше: правило прав однакове для сторінки, дії й прямого запиту; поведінка перевіряється тестами бази на PGlite у CI `app` без Docker (`tests/db/template-versions.test.ts`).
- Складніше: кожна нова привілейована дія — функція в `private` з обгорткою в `public`; помилки бази сторінки й дії перекладають у тексти AC; форма запуску читає знімок, а не робочу копію.
- Якщо PM відповість на питання solomchaak/property-workflows-spec#21–#36 інакше, зміниться лише поведінка функцій у відповідних місцях.

## Як перевіряємо

- PGlite (`tests/db/template-versions.test.ts`):
  - менеджер бачить версію 1 з 5 задачами й не бачить робочу копію, чернетку та версії (AC-EDITOR-02, AC-EDITOR-07);
  - менеджер не змінює таблиці й не викликає функції запису, дані не змінились (AC-EDITOR-08); гість — те саме;
  - шаблон без обов'язкової задачі не зберігається, версії немає, зміни лишаються (AC-EDITOR-04);
  - запуск зберігає версію й секції після зміни шаблону (AC-EDITOR-06, AC-RUN-02, AC-RUN-12).
- Мутаційна перевірка в PR: прибрана перевірка ролі в `save_template_draft`; менеджеру додана політика читання робочої копії; прибрана перевірка обов'язкової задачі в `publish_template` → відповідні тести червоні (посилання на прогони CI в описі PR).
- `npm run check:boundary` (`architecture.yml`): секретний ключ не потрапляє в клієнтський код; admin-клієнт тут не потрібен.
